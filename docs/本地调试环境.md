# 本地调试环境搭建

以下以 Jellyfin 12.2、macOS arm64 和 Rider 为例。命令均从仓库根目录执行；其他系统需要下载对应平台的 Jellyfin，并使用该平台的符号链接命令。

## 环境要求

- 与插件目标框架匹配的 .NET SDK，当前为 .NET 10 SDK。
- Node.js 22.12 或更高版本，以及 npm。
- FFmpeg 和 ffprobe，需要能通过 `PATH` 找到。macOS 可通过 `brew install ffmpeg` 安装。
- Rider，用于启动和断点调试；也可以先通过命令行验证启动。

当前 Jellyfin 插件目标框架为 `net10.0`，引用 Jellyfin 12 的接口。目标框架会随 Jellyfin 和插件依赖的升级而变化，并非固定使用 `net10.0`；请以 `Jellyfin.Plugin.Bangumi/Jellyfin.Plugin.Bangumi.csproj` 中的 `TargetFramework` 和 `Directory.Packages.props` 中的 Jellyfin 依赖版本为准，选择相应的 SDK 和服务端版本。其他 Jellyfin 主版本需要对应版本的插件代码，不能只修改运行配置中的目录名。

## 下载 Jellyfin

从 [Jellyfin 官方下载仓库](https://repo.jellyfin.org/)选择对应系统、架构和版本的服务端包。macOS arm64 的 12.2 可以这样下载和解压：

```sh
mkdir -p debug/jellyfin-12.2
curl -fL --retry 2 \
  https://repo.jellyfin.org/files/server/macos/stable/v12.2/arm64/jellyfin_12.2-arm64.tar.xz \
  -o debug/jellyfin_12.2-arm64.tar.xz
tar -xf debug/jellyfin_12.2-arm64.tar.xz \
  -C debug/jellyfin-12.2 --strip-components=1
```

解压后应有以下文件和目录：

```text
debug/
└── jellyfin-12.2/
    ├── jellyfin
    ├── jellyfin.dll
    ├── jellyfin-web/
    └── data/                 # 首次启动时创建，或提前复制测试数据
```

`debug/` 已被 Git 忽略，服务端程序、数据库、插件配置和日志都放在这里，不提交到仓库。

## 构建并安装调试插件

先构建 Debug 插件，并发布一份包含运行依赖的文件，供首次安装使用：

```sh
dotnet publish Jellyfin.Plugin.Bangumi/Jellyfin.Plugin.Bangumi.csproj \
  --configuration Debug --output debug/bangumi-plugin
```

构建会自动安装前端依赖、生成前端产物并嵌入 DLL，因此首次构建需要联网。生成后的插件主文件位于 `Jellyfin.Plugin.Bangumi/bin/Debug/<TargetFramework>/`，当前对应 `net10.0`；发布目录还包含插件需要的依赖 DLL。

创建插件目录，复制依赖，并将主 DLL、调试符号和依赖描述文件软链接到 Debug 构建目录：

```sh
bangumi_target_framework=$(dotnet msbuild Jellyfin.Plugin.Bangumi/Jellyfin.Plugin.Bangumi.csproj \
  -getProperty:TargetFramework -nologo)

mkdir -p debug/jellyfin-12.2/data/plugins/bangumi

for bangumi_dependency in debug/bangumi-plugin/*.dll; do
  case "$bangumi_dependency" in
    */Jellyfin.Plugin.Bangumi.dll) continue ;;
  esac
  cp "$bangumi_dependency" debug/jellyfin-12.2/data/plugins/bangumi/
done

for bangumi_suffix in dll pdb deps.json; do
  ln -s "../../../../../Jellyfin.Plugin.Bangumi/bin/Debug/$bangumi_target_framework/Jellyfin.Plugin.Bangumi.$bangumi_suffix" \
    "debug/jellyfin-12.2/data/plugins/bangumi/Jellyfin.Plugin.Bangumi.$bangumi_suffix"
done
```

上述命令通过 MSBuild 读取当前目标框架。软链接通常只需创建一次；目标框架变化后，需要重新创建链接，避免仍指向旧框架的构建产物。若插件目录已经存在同名文件或旧链接，需要先移到备份目录或废纸篓，再创建链接；不要在其他插件子目录中同时保留另一份 Bangumi 主 DLL。

可检查链接是否指向实际存在的构建产物：

```sh
ls -l debug/jellyfin-12.2/data/plugins/bangumi/Jellyfin.Plugin.Bangumi.*
test -f debug/jellyfin-12.2/data/plugins/bangumi/Jellyfin.Plugin.Bangumi.dll
```

如需复用已有测试环境，先停止源实例和目标实例，再将原来的整个数据目录复制到 `debug/jellyfin-12.2/data/`，然后检查上面的插件链接和依赖。新版本首次启动会迁移复制后的数据；保留原数据目录用于旧版本测试。迁移前还应检查复制的配置是否含有指向原目录的自定义绝对路径。

## 启动和断点调试

### Rider

打开 `Jellyfin.Plugin.Bangumi.sln`，选择仓库提供的 **Jellyfin 12.2** 运行配置，再使用 Debug 启动。

运行配置会先构建解决方案，再启动 `debug/jellyfin-12.2/jellyfin.dll`，工作目录为 `debug/jellyfin-12.2/`，通过 `--datadir` 指定独立的数据目录。插件 DLL 和 PDB 的软链接使每次 Debug 构建的结果可以直接被加载，无需反复复制主 DLL。

首次启动时打开 <http://127.0.0.1:8096> 完成设置向导，创建管理员和测试媒体库，并在媒体库设置中按需启用 Bangumi 元数据及图片来源。已有数据目录会保留原来的账号和媒体库设置。启动日志应包含 `Loaded plugin: Bangumi`。

### 命令行

如果想先确认环境能够启动，可以在仓库根目录执行：

```sh
(
  cd debug/jellyfin-12.2
  dotnet jellyfin.dll --datadir "$PWD/data/"
)
```

启动后检查健康状态和服务端版本：

```sh
curl -fsS http://127.0.0.1:8096/health
curl -fsS http://127.0.0.1:8096/System/Info/Public
```

健康检查应返回 `Healthy`，版本信息应包含 `12.2.0`。默认 HTTP 端口为 `8096`；使用复制的数据时，以原网络配置为准。同一端口只能运行一个实例，从命令行切换到 Rider 调试前，先按 Ctrl+C 停止命令行实例。

## 前端热重载（可选）

默认运行配置不设置前端开发服务器，插件使用构建时嵌入的前端文件。

需要实时调试前端时，先在一个终端运行：

```sh
npm --prefix web run dev
```

然后在 Rider 的 **Jellyfin 12.2 → 环境变量** 中新增：

```text
BANGUMI_WEB_DEV_SERVER=http://127.0.0.1:8765
```

变量名开头没有下划线。通过命令行启动时，则将启动命令改为：

```sh
(
  cd debug/jellyfin-12.2
  BANGUMI_WEB_DEV_SERVER=http://127.0.0.1:8765 \
    dotnet jellyfin.dll --datadir "$PWD/data/"
)
```

重启 Jellyfin 后，打开正常的 Bangumi 插件配置页，浏览器会从 Vite 加载前端源码，继续使用真实的 Jellyfin API 和测试数据。此时修改前端会自动刷新页面，未保存的表单内容可能丢失。该变量仅对 Debug 插件生效；关闭热重载时，移除变量并重启 Jellyfin、刷新页面。

更多前端构建、跨设备访问及调试说明见 [web/README.md](../web/README.md#live-development-inside-jellyfin)。

## 修改代码后的操作

- 修改 C#：停止 Jellyfin，重新构建 Debug 插件，再启动。软链接不会让已加载的程序集自动更新。
- 修改前端：热重载开启时由 Vite 刷新；使用内嵌前端时，需要重新构建插件并重启 Jellyfin。
- 更新 NuGet 运行依赖：重新执行 Debug 发布和依赖复制步骤，随后重启 Jellyfin；已有软链接无需重复创建。
- 测试某个 PR：先切换到对应分支，再构建和重启。加载的是软链接所指向工作目录中最后一次成功构建的产物。

日志位于 `debug/jellyfin-12.2/data/log/`。断点无法命中时，先确认正在运行的是 Debug 插件、DLL 和 PDB 均来自当前构建，并检查是否加载了其他目录中的同名插件。
